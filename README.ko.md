# AlarmControl

[English](README.md) | **한국어**

규칙, 로컬 통계, 온디바이스 AI를 사용하는 오프라인 우선 Android 알림 필터입니다.

AlarmControl은 사용자가 만든 규칙에 따라 기기에서 알림을 평가하고 취소, 다시 알림, 유지
또는 기록합니다. 설치된 앱에는 계정, 원격 분석, 클라우드 서비스, 모델 다운로드,
`INTERNET` 권한이 없습니다. 알림 데이터는 기기 밖으로 나가지 않습니다.

> **범위:** AlarmControl은 Android가 알림을 게시한 뒤 처리합니다. 알람을 예약하지 않고,
> 알림으로 나타나지 않는 시스템 알람을 가로채지 않으며, 다른 앱의 알림을 읽음 처리하거나
> 헤드업 알림이 전혀 나타나지 않는다고 보장하지 않습니다.

> **배포:** GitHub Releases를 바이너리 배포 경로로 사용합니다. 같은 Release에
> `AlarmControl-<version>-universal.apk`와 `.sha256` 파일이 모두 있을 때만 설치하세요.
> GitHub가 자동 생성한 소스 압축 파일은 Android 설치 파일이 아닙니다. 두 파일이 없다면
> 해당 버전에는 설치 가능한 공개 릴리스가 없는 것입니다.

## 빠른 시작

1. Android 8.0 이상 기기를 사용합니다.
2. 같은 GitHub Release에서 서명된 범용 APK와 체크섬을 받습니다.
3. APK를 여는 브라우저 또는 파일 관리자에만 **출처를 알 수 없는 앱 설치**를 허용합니다.
4. AlarmControl을 열고 **알림 접근 권한**을 허용합니다.
5. 먼저 **관찰** 규칙을 만듭니다.
6. **통계 → 기록**에서 예상 결과를 확인합니다.
7. 일치 결과가 안전한 경우에만 규칙을 **활성**으로 바꿉니다.

번들 분류기는 별도 모델 파일 없이 작동합니다. 일반 필터링에는 선택형 생성 LLM이 필요하지
않습니다.

체크섬 확인, 업데이트, 백업, 안전한 규칙 설정, 자동화, 문제 해결은
[사용 설명서](docs/USER_GUIDE.ko.md)를 참고하세요.

## 주요 기능

- **규칙 우선 처리:** 앱, 채널, 제목·본문, Android 카테고리, 시간, 빈도, 중요도, 대화,
  포그라운드 서비스, 로컬 ML 카테고리, 의미 의도를 조건으로 사용할 수 있습니다.
- **안전한 실행 모드:** 관찰은 알림을 바꾸지 않고 예상 결과만 기록합니다. 활성은 우선순위에
  따라 처음 일치한 규칙의 동작을 수행할 수 있습니다.
- **정확한 동작 범위:** 취소와 다시 알림만 Android 알림 API를 호출합니다. 유지와 기록만은
  숨겨진 플랫폼 동작 없이 판정만 기록합니다.
- **온디바이스 분류:** 번들 로컬 모델이 일반 카테고리와 7종 의미를 분류합니다. 누락,
  모호함, 시간 초과, 낮은 신뢰도는 fail-open 처리합니다.
- **로컬 교정 학습:** 사용자가 명시적으로 고친 라벨은 런타임 역전파나 데이터 내보내기 없이
  패키지별 예측에 로컬로 반영됩니다.
- **통계와 기록:** 활동, 기간 추세, 앱·채널·규칙 분포, 판정 트레이스, 보수적인 규칙 제안을
  확인할 수 있습니다.
- **프로필과 자동화:** 여러 규칙을 프로필로 묶고 앱, 빠른 설정, 런처 바로가기, Samsung
  모드 및 루틴, Tasker, MacroDroid에서 제어할 수 있습니다.
- **로컬 백업과 복원:** 규칙, 프로필, 선택한 설정, 일별 요약을 사용자가 고른 파일로
  내보내며 비밀번호 암호화를 선택할 수 있습니다.

## 안전한 규칙 사용법

AlarmControl은 활성과 관찰 목록을 독립적으로 평가합니다.

- **관찰**은 취소하거나 다시 알리지 않고 예상 동작만 기록합니다.
- **활성**은 신뢰할 수 있는 일치 후 알림을 취소하거나 다시 알릴 수 있습니다.
- 각 목록에서는 우선순위가 높은 규칙부터 평가합니다.
- 사용할 수 없는 신호는 일치가 아니라 `UNKNOWN`입니다.
- 높은 우선순위의 유지 규칙으로 알람, 통화·대화, 진행 중 서비스, 중요 알림을 명시적으로
  보호할 수 있습니다.

새 파괴적 동작 초안은 관찰 모드로 시작합니다. 템플릿과 추천은 편집 가능한 초안만 열며
자동 저장하거나 활성화하지 않습니다. 규칙 편집기의 시험 기능도 실제 알림에는 영향을 주지
않습니다.

조건과 우선순위의 상세 동작은 [규칙 안내](docs/RULES_GUIDE.ko.md)를 참고하세요.

## 구조적으로 보장하는 개인정보 보호

- 최종 병합된 앱·테스트 APK 매니페스트는 `android.permission.INTERNET` 권한을 부여하지
  않습니다.
- 런타임 모듈에는 네트워크 클라이언트, 원격 분석·충돌 업로더, 원격 모델 다운로드 기능이
  없습니다.
- 일반 활동 기록에는 알림 제목이나 본문이 아닌 메타데이터만 저장합니다.
- 선택형 알림 상세 저장은 기본값이 꺼져 있습니다. 켜면 대상이 되는 이후 제목·본문을 길이
  제한 후 Android Keystore AES-256-GCM으로 암호화하고 7일 뒤 삭제합니다. 비밀 알림과
  사용자가 제외한 앱은 저장하지 않습니다.
- 알림 내용, LLM reasoning, 자동화 토큰, 비밀번호, 암호화 키는 휴대용 백업에 포함하지
  않습니다.
- Android OS 클라우드 백업을 끄고, 사용자가 실행하는 백업·모델 선택기는 로컬 공급자만
  요청합니다.

전체 저장·삭제 경계는 [개인정보와 로컬 데이터 안내](docs/PRIVACY.ko.md)를 참고하세요.

## 기기 내 AI

일반 필터링에는 두 가지 번들 로컬 경로가 포함됩니다.

1. 홍보, 소셜, 뉴스, 알람 등의 라벨을 위한 경량 카테고리 분류기
2. `MARKETING`, `TRANSACTIONAL`, `SECURITY`, `DELIVERY`, `SOCIAL`, `OTHER`,
   `AMBIGUOUS`를 위한 7종 의미 인코더

신뢰할 수 있는 번들 의미 결과만 활성 규칙 신호로 사용할 수 있습니다. 모델·어휘·라벨·
매니페스트는 해시로 묶인 자산이며 분류 실패 시 알림을 그대로 둡니다.

별도의 MediaPipe `.task` 생성 LLM은 호환성 작업을 위해 로컬 저장소에서 직접 가져올 수
있습니다. AlarmControl은 모델을 다운로드하지 않습니다. 현재 빌드에는 검증된 자동 백그라운드
LLM 프로필이 없으며 생성 결과는 관찰 전용이므로 이미 처리된 알림을 나중에 취소하거나 다시
알리지 않습니다.

학습·변환·평가 상세는 [의미 분류 파이프라인](ml/semantic-training/README.ko.md)과
[LLM 파이프라인](ml/llm-training/README.ko.md)을 참고하세요.

## 설치와 업데이트

가능하면 설치 전에 APK 체크섬을 확인하세요. 체크섬은 APK가 같은 Release의 체크섬 파일과
일치하는지 확인하지만, 그 자체로 게시자의 신원을 독립적으로 인증하지는 않습니다. 이후
Android 패키지 서명은 업데이트 서명키가 계속 같은지 강제합니다.

업데이트는 기존 앱 위에 새 APK를 설치합니다. 먼저 앱을 제거하면 로컬 데이터가 삭제되므로
제거하지 마세요. Android는 새 APK의 `versionCode`가 더 크고 서명키가 기존 설치와 같을
때만 제자리 업데이트를 허용합니다. AlarmControl은 GitHub를 확인하거나 스스로 업데이트하지
않습니다.

GitHub는 기기별로 ABI를 선택하지 않으므로 범용 APK에는 지원하는 모든 native ABI가
포함됩니다. 선택형 생성 LLM은 별도 파일이며 APK에 포함되지 않습니다.

자세한 설치, 체크섬, 개발 빌드 전환, 복구 방법은
[사용 설명서](docs/USER_GUIDE.ko.md)를 참고하세요.

## 자동화

Samsung 모드 및 루틴은 AlarmControl의 자사 App Shortcut을 사용하므로 자동화 토큰이
필요하지 않습니다. 빠른 설정과 런처 바로가기도 같은 로컬 프로필 제어기를 사용합니다.

Tasker, MacroDroid 및 호환 도구는 별도의 명시적 브로드캐스트 계약을 사용합니다. 이 경로는
기본값이 꺼져 있고 설정에 표시되는 설치별 토큰이 필요합니다. 암시적 브로드캐스트는 거부하며
요청 횟수도 로컬에서 제한합니다.

[Samsung Routines, Tasker, MacroDroid 자동화 안내](docs/automation.ko.md)를 참고하세요.

## 소스에서 빌드

JDK 17, Gradle Wrapper, Android SDK 36을 사용합니다.

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
./gradlew assembleDebug
./gradlew check
```

`assembleDebug`는 자동으로 Debug 서명된 개발 APK를 만듭니다. GitHub에 배포할 APK는
장기 보관할 Release 키를 사용하고 `:app:releaseCandidate`를 통과해야 합니다. 자세한 내용은
[BUILD.ko.md](BUILD.ko.md)를 참고하세요. 키 저장소나 서명 정보는 커밋하지 마세요.

## 아키텍처

Kotlin, Coroutines/Flow, Jetpack Compose, Hilt, Room, DataStore, WorkManager, LiteRT와
선택형 MediaPipe Tasks GenAI를 사용합니다.

| 모듈 | 책임 |
|---|---|
| `:app` | Compose UI, 탐색, 의존성 연결, 알림 리스너 진입점 |
| `:core` | 프레임워크 독립 모델과 저장소 계약 |
| `:data` | Room, DataStore, 백업, 암호화, 저장소 구현 |
| `:ml` | 번들 분류기, 로컬 교정, 선택형 로컬 LLM 경계 |
| `:notifications` | 순수 Kotlin 규칙 매칭과 설명 로직 |
| `:automation` | 인증 Intent, 바로가기, 프로필, 빠른 설정 |
| `:baselineprofile` | 빌드 전용 시작 프로필과 벤치마크 도구 |

출시 게이트는 포맷, 정적 분석, 테스트, 의존성 무결성, 오프라인 매니페스트·클래스패스,
모델 자산, APK 용량 제한, APK 서명 유효성을 검사합니다. 컴파일됐거나 서명되지 않은
APK/AAB는 게시 가능한 릴리스가 아닙니다.

Galaxy Note20 5G의 Android 13 / One UI 5.1 환경에서 실기기 검증을 진행했습니다.
기기별 결과는 해당 구성의 증거이며 모든 Android 기기의 성능을 보장하지 않습니다.
