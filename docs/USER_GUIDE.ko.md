# AlarmControl 사용 설명서

[English](USER_GUIDE.md) | **한국어**

이 문서는 GitHub Releases에서 AlarmControl을 설치하고, 안전하게 설정하고, 주요 기능을
사용하며, 일반적인 문제를 해결하는 방법을 안내합니다.

AlarmControl은 오프라인 알림 필터입니다. 계정, 클라우드 서비스, 원격 분석, 자동 업데이트,
런타임 네트워크 접근이 없습니다. Android가 알림을 게시한 뒤 기기 안에서 평가합니다.

## 시스템 요구 사항

- Android 8.0(API 26) 이상
- 알림 리스너 접근 권한을 허용할 수 있는 Android 기기
- 선택한 APK 하나와 설치된 앱을 위한 충분한 저장 공간
- 이 저장소의 GitHub Releases에서 APK를 안전하게 받을 수 있는 방법

모든 APK 변형에는 같은 번들 경량 의미 분류기가 들어 있습니다. 일반 필터링에는 별도로
내려받는 모델이 필요하지 않습니다. 선택형 생성 LLM은 사용자가 별도로 준비하는 파일이며
초기 설정과 관계없습니다.

## GitHub Releases에서 설치

### 1. 올바른 파일 받기

저장소의 [Releases 페이지](../../../releases)를 엽니다. 현재 워크플로로 만드는 Release에는
같은 업데이트 키로 서명한 APK 5개와 각각에 맞는 체크섬이 있습니다. 이전에 검증한
Release에는 범용 APK와 체크섬 한 쌍만 있을 수 있습니다.

```text
AlarmControl-<version>-<variant>.apk
AlarmControl-<version>-<variant>.apk.sha256
```

다음 중 하나를 선택합니다.

| 변형 | 사용 대상 |
|---|---|
| `arm64-v8a` | 대부분의 최신 Android 휴대전화와 태블릿 |
| `armeabi-v7a` | 오래된 32비트 ARM 기기 |
| `x86_64` | 주로 64비트 에뮬레이터와 일부 Intel 기반 특수 기기 |
| `x86` | 주로 오래된 32비트 에뮬레이터와 일부 Intel 기반 특수 기기 |
| `universal` | 지원하는 모든 ABI. 잘 모르겠다면 이 파일을 선택 |

GitHub는 Google Play처럼 기기를 판별해 APK를 자동으로 골라 주지 않습니다. APK는 하나만
받고, 변형 이름이 같은 `.sha256` 파일을 함께 받으세요. 고급 사용자는 ADB로 기기가
우선 사용하는 ABI를 확인할 수 있습니다.

```sh
adb shell getprop ro.product.cpu.abi
```

GitHub가 자동 생성하는 **Source code (zip)** 또는 **Source code (tar.gz)**는 설치 파일이
아닙니다. 선택한 APK나 이름이 같은 체크섬이 없다면 그 Release를 설치하지 마세요.

### 2. 다운로드 확인

macOS:

```sh
shasum -a 256 -c AlarmControl-<version>-<variant>.apk.sha256
```

Linux:

```sh
sha256sum -c AlarmControl-<version>-<variant>.apk.sha256
```

Windows PowerShell에서는 두 값을 출력해 비교합니다.

```powershell
Get-FileHash -Algorithm SHA256 .\AlarmControl-<version>-<variant>.apk
Get-Content .\AlarmControl-<version>-<variant>.apk.sha256
```

`<version>`과 `<variant>`는 받은 파일 이름에 맞게 바꾸세요. 해시가 일치해야 합니다.
체크섬은 다운로드가 바뀌거나 불완전하지 않은지 확인하고 APK가 같은 Release의 체크섬
파일과 일치하는지 보여줍니다. 두 파일을 누가 게시했는지 독립적으로 증명하지는 않으므로
신뢰하는 저장소에서만 받으세요.

### 3. APK 설치

1. Android 기기에서 APK를 엽니다.
2. Android가 요청하면 APK를 여는 브라우저 또는 파일 관리자에 **출처를 알 수 없는 앱
   설치**를 허용합니다.
3. 설치를 확인합니다.
4. 설치 후 해당 앱의 설치 허용을 다시 꺼도 됩니다.

제조사와 OS 버전에 따라 메뉴 문구와 경로가 다릅니다. 확인한 APK를 현재 여는 앱에만 설치
예외를 허용하세요.

## 데이터 손실 없이 업데이트

새 Release에서 호환 APK 하나와 이름이 같은 체크섬을 받고 확인한 다음 기존 AlarmControl
위에 APK를 설치합니다.

먼저 앱을 **제거하지 마세요**. 제거하면 로컬 규칙, 프로필, 기록, 설정, 암호화 상세,
가져온 모델 파일이 삭제됩니다. Android는 다음 두 조건을 모두 만족할 때만 제자리 업데이트를
허용합니다.

- 새 APK의 `versionCode`가 더 큼
- 설치된 앱과 새 APK의 Release 서명키가 같음

Android가 서명 충돌을 표시하면 설치를 멈추고 다운로드 출처를 확인하세요. 로컬 Debug APK와
공식 Release APK는 서로 다른 키를 사용하므로 바로 업데이트할 수 없습니다. 의도적으로
Debug 설치를 Release로 바꿔야 한다면:

1. **설정 → 백업 및 복원**을 엽니다.
2. 로컬 백업을 만듭니다.
3. 백업 파일을 열 수 있고 안전한 위치에 있는지 확인합니다.
4. Debug 빌드를 제거합니다.
5. Release APK를 설치합니다.
6. 백업에서 선택한 데이터를 복원합니다.

암호화된 알림 상세, 자동화 토큰, 가져온 LLM은 휴대할 수 없으므로 Debug에서 Release로
교체할 때 사라집니다.

AlarmControl은 GitHub를 확인하거나 업데이트를 직접 내려받지 않습니다.

## 첫 실행과 알림 접근 권한

AlarmControl은 **규칙** 화면으로 시작합니다. 필수 설정은 알림 접근 권한입니다.

1. 알림 접근 카드의 **설정 열기**를 누릅니다.
2. Android 알림 접근 화면에서 **AlarmControl 알림 필터링**을 켭니다.
3. Android 경고를 읽고, 알림 리스너가 알림을 볼 수 있다는 점에 동의할 때만 허용합니다.
4. AlarmControl로 돌아옵니다.
5. **설정 → 앱 상태**에서 **알림 접근 권한: 준비됨**인지 확인합니다.

알림 접근은 Android가 새 알림의 메타데이터와 내용을 로컬 평가용 리스너에 전달하는 강한
권한입니다. AlarmControl은 이를 기기에서 처리하며 `INTERNET` 권한이 없습니다.

알림 접근을 해제하면 이후 필터링과 기록이 중단됩니다. 기존 로컬 데이터는 자동 삭제되지
않으므로 삭제하려면 **설정 → 데이터 및 개인정보**를 사용하세요.

### 배터리 설정

설정 화면은 현재 배터리 정책도 보여줍니다. AlarmControl을 배터리 최적화에서 제외하는 것은
선택 사항입니다. 일반 최적화가 켜져 있으면 주기적인 일별 요약이 늦어질 수 있지만 알림
리스너와 실시간 기록은 그 일정과 분리되어 있습니다.

### 앱 언어 변경

AlarmControl은 영어와 한국어 화면을 모두 제공합니다. **설정 → 앱 언어**에서 **시스템
기본값**, **English**, **한국어** 중 하나를 선택하세요. 언어를 바꾸면 Android가 번역
리소스를 다시 읽도록 현재 화면이 재생성되지만 규칙이나 로컬 데이터는 삭제되지 않습니다.
Android 13 이상에서는 Android의 앱별 언어 설정과 같은 선택값을 사용합니다.

## 안전한 첫 규칙 설정

자동 취소를 허용하기 전에 다음 순서로 확인하세요.

1. **규칙**에서 **규칙 추가**를 누릅니다.
2. 최근 관찰한 앱이나 채널을 선택합니다. 관찰된 소스가 없으면 `com.example.app` 같은
   올바른 Android 패키지명을 입력합니다.
3. 동작을 선택합니다.
4. 실행 모드는 **관찰**로 둡니다.
5. 필요하면 시간대나 반복 알림 임계치를 추가합니다.
6. 알아보기 쉬운 이름을 입력하고 저장합니다.
7. 대표적인 실제 알림이 도착하기를 기다립니다.
8. **통계 → 기록**에서 예상 동작과 조건 트레이스를 확인합니다.
9. 일치 결과가 안전한 경우에만 규칙을 편집해 **활성**으로 바꿉니다.

이 과정에서 파괴적 규칙이 자동으로 활성화되지는 않습니다.

## 동작과 실행 모드

### 동작

| 동작 | 효과 |
|---|---|
| **취소** | Android를 통해 일치한 게시 알림을 닫습니다. |
| **다시 알림** | 선택한 시간 동안 알림을 숨기도록 Android에 요청합니다. |
| **유지** | 허용 판정을 기록하고 우선순위가 낮은 활성 규칙이 동작하지 않게 합니다. |
| **기록만** | 알림을 바꾸지 않고 판정만 기록합니다. |

유지와 기록만은 다른 앱의 알림을 읽음 처리하지 않으며 숨겨진 플랫폼 동작도 없습니다.

### 관찰과 활성

| 모드 | 효과 |
|---|---|
| **관찰** | 규칙이 수행할 동작을 기록하지만 취소하거나 다시 알리지 않습니다. |
| **활성** | 신뢰할 수 있는 첫 일치 동작을 실제로 적용할 수 있습니다. |

활성 규칙과 관찰 규칙은 독립된 목록에서 평가합니다. 각 목록에서는 숫자 우선순위가 높은
규칙부터 실행하고 처음 확실히 일치한 규칙이 이깁니다. 꺼진 규칙은 평가하지 않습니다.

필요한 정보가 없으면 조건 결과는 `UNKNOWN`입니다. `UNKNOWN`은 동작 가능한 일치가 아니므로
알림을 그대로 둡니다.

## 규칙 만들기와 시험

안내형 편집기는 일반적인 흐름을 지원합니다.

- 앱 전체 또는 관찰한 한 채널 선택
- 취소, 다시 알림, 유지 선택
- 선택적으로 현지 시간대 제한
- 선택적으로 앱 또는 앱+채널의 반복 알림 조건
- 이름 지정 후 저장

**이 규칙 시험하기**에서 예시 메타데이터를 입력하고 `일치`, `불일치`, `신호 없음`을
확인할 수 있습니다. 시험 기능은 실제 알림을 바꾸지 않습니다.

템플릿은 편집 가능한 미저장 시작점입니다. 보호 템플릿은 알람, 대화, 포그라운드 서비스,
중요 알림을 위한 높은 우선순위의 유지 초안을 만듭니다. 저장 전에 모든 템플릿을
검토하세요.

### 고급 조건

고급 편집기는 다음을 지원합니다.

- 패키지, 제목, 본문, Android 카테고리, 채널
- 로컬 ML 카테고리와 7종 의미 의도
- 지속 알림, 대화, 포그라운드 서비스 상태
- Android 중요도
- 현지 시간과 알림 빈도
- 중첩된 모두, 하나 이상, NOT 그룹

형제 조건 순서는 평가 순서를 결정하고 규칙 우선순위는 일치한 규칙 중 무엇이 이기는지
결정합니다. 제한, 빈도 의미, 상세 예시는 [규칙 안내](RULES_GUIDE.ko.md)를 참고하세요.

## 통계와 기록 사용

**통계**에는 세 탭이 있습니다.

- **개요:** 오늘 집계, 최근 활동, 일별 카드, 로컬 제안
- **분석:** 보관 기간의 추세와 앱·규칙·채널·카테고리·시간·의미·로컬 학습 분포
- **기록:** 검색 가능한 로컬 판정 기록, 동작·소스 필터, 상세

기록 목록은 알림 내용을 복호화하지 않고 메타데이터만 읽습니다. 해당 알림이 도착하기 전에
선택형 상세 저장을 켜 둔 경우에만 한 기록의 **상세**를 열어 암호화된 제목·본문을 읽습니다.

기록에서는 다음을 할 수 있습니다.

- 활성 결과, 관찰 예상, 신뢰도, 제한된 조건 트레이스 확인
- 로컬 카테고리 또는 의미 라벨 교정
- Android 앱·채널 알림 설정 열기
- 해당 소스의 규칙 초안 열기
- 높은 우선순위의 유지 초안 열기
- 통계에서 기록 제외

**통계에서 제외**는 이후 로컬 집계만 바꿉니다. 이미 취소하거나 다시 알림 처리한 알림을
복구하지 못합니다.

규칙 제안은 로컬 초안이며 자동 저장하거나 활성화하지 않습니다.

## 프로필 관리

프로필은 하나 이상의 기존 규칙을 묶습니다.

1. **프로필**을 엽니다.
2. **프로필 추가**를 누릅니다.
3. 고유한 이름을 입력하고 규칙을 하나 이상 선택합니다.
4. 프로필을 저장합니다.

꺼졌거나 일부만 활성인 프로필을 전환하면 구성 규칙을 모두 켭니다. 완전히 활성인 프로필을
전환하면 구성 규칙을 모두 끕니다. 프로필을 삭제해도 원래 규칙은 남습니다.

앱, 런처 바로가기, 빠른 설정, Samsung Routines, 인증된 외부 자동화가 모두 같은 프로필
동작을 사용합니다.

## 전체 필터링 일시 중지

개별 규칙 스위치를 바꾸지 않고 AlarmControl을 멈추거나 다시 시작하려면
**설정 → 필터링 사용**을 사용합니다. 일시 중지 중에는:

- 알림을 필터링하지 않습니다.
- 새 활동 기록을 저장하지 않습니다.
- 기존 규칙과 프로필은 유지합니다.

빠른 설정 타일과 자사 바로가기도 같은 마스터 스위치를 제어합니다.

## 자동화

### Samsung 모드 및 루틴

Samsung Routines는 AlarmControl의 **필터링 켜기**, **필터링 일시 중지**, 게시된 프로필
App Shortcut을 실행할 수 있습니다. 이 자사 경로에는 **외부 자동화 허용**이나 인증 토큰이
필요하지 않습니다.

메뉴 이름은 One UI 버전에 따라 다릅니다. 검증한 설정 과정은
[자동화 안내](automation.ko.md)를 참고하세요.

### 빠른 설정과 런처 바로가기

- Android 빠른 설정 편집 화면에서 **AlarmControl filtering** 타일을 추가합니다.
- 런처에서 AlarmControl 아이콘을 길게 눌러 필터링 및 프로필 바로가기를 사용합니다.

이 자사 제어에는 외부 자동화 동의가 필요하지 않습니다.

### Tasker와 MacroDroid

Tasker, MacroDroid 및 호환 도구는 별도의 공개 Intent 계약을 사용합니다.

1. **설정 → 자동화**를 엽니다.
2. **외부 자동화 허용**을 켭니다.
3. 현재 설치별 토큰을 표시하고 복사합니다.
4. AlarmControl 패키지 또는 수신기 component를 명시합니다.
5. 토큰을 필수 String extra로 추가합니다.

토큰을 다시 생성하면 기존 자동화가 즉시 무효가 됩니다. 토큰을 로그, 스크린샷, 암시적
브로드캐스트, 공유 작업 파일에 넣지 마세요. 정확한 action과 extra는
[자동화 안내](automation.ko.md)에 있습니다.

## 알림 상세 기록

기본값에서 AlarmControl은 알림 내용이 없는 판정 메타데이터만 저장합니다.

암호화 상세를 사용하려면:

1. **설정 → 데이터 및 개인정보**를 엽니다.
2. **알림 제목과 내용 저장**을 켭니다.
3. **앱 제외 관리**를 열어 민감한 앱의 저장을 끕니다.

이 설정은 대상이 되는 이후 알림에만 적용됩니다. 내용은:

- 길이 제한 후 Android Keystore AES-256-GCM 키로 암호화됩니다.
- 목록과 통계 쿼리에서 읽지 않습니다.
- Android `SECRET` 알림이나 제외 앱에서는 저장하지 않습니다.
- 7일 뒤 자동 삭제됩니다.
- 휴대용 백업에 포함하지 않습니다.

기능 끄기에 성공하면 AlarmControl은 설정을 꺼진 상태로 표시하기 전에 모든 암호문과
내보낼 수 없는 키를 삭제합니다. 삭제에 실패하면 설정을 켜진 상태로 유지하고 다시
시도하도록 안내합니다. 알림이 도착할 때 저장 기능이 꺼져 있었거나, 7일이 지났거나, 앱이
제외됐거나, Android가 비밀 알림으로 표시했거나, 로컬 키가 삭제된 경우에도 상세를 볼 수
없습니다.

## 보존 기간과 삭제

**설정 → 데이터 및 개인정보**에서 활동 기록과 일별 요약 보존 기간을 각각 설정합니다.
원본 활동은 최신 10,000건, 상세 조건 트레이스는 최신 1,000건으로도 제한됩니다.

다음 데이터를 따로 삭제할 수 있습니다.

- 암호화된 알림 상세
- 활동 기록
- 로컬 교정 학습
- 일별 통계
- 전체 앱 데이터

삭제는 로컬에서 즉시 적용되며 되돌릴 수 없습니다. **전체 앱 데이터 초기화**는 규칙,
프로필, 설정, 추천, 가져온 LLM 파일, 암호화 내용과 키도 제거합니다.

## 백업과 복원

**설정 → 백업 및 복원**을 엽니다.

### 백업 만들기

1. 필요하면 8자 이상의 비밀번호를 입력합니다.
2. 암호화를 켠 경우 패키지별 교정 학습 포함 여부를 선택합니다.
3. **백업**을 누릅니다.
4. Android 파일 선택기에서 기기 내 위치를 고릅니다.

비밀번호가 없으면 내보낸 JSON은 읽을 수 있는 평문 파일이므로 주의해서 보관해야 합니다.
암호화 내보내기는 비밀번호 기반 AES-256-GCM을 사용합니다.

백업에는 규칙, 프로필, 선택한 설정, 일별 요약, 선택형 암호화 학습 투표가 들어갈 수
있습니다. 알림 제목·본문, LLM reasoning, 가져온 LLM 파일, 자동화 토큰, 비밀번호,
암호화 키는 들어가지 않습니다.

### 백업 복원

1. 암호화 파일이면 먼저 비밀번호를 입력합니다.
2. **복원**을 누르고 로컬 백업을 선택합니다.
3. 개수와 복원 가능한 구역을 확인합니다.
4. **병합** 또는 **선택 항목 교체**를 고릅니다.
5. 복원할 구역을 선택합니다.
6. **선택 항목 복원**을 확인합니다.

AlarmControl은 로컬 상태를 바꾸기 전에 백업을 검증합니다. 중요한 백업은 별도 사본을
보관하고 앱 제거 또는 초기화 전에 파일을 열 수 있는지 확인하세요.

## 기기 내 AI와 선택형 LLM

### 번들 분류기

카테고리 분류기와 7종 의미 분류기는 APK에 포함되어 별도 모델 파일 없이 로컬에서 실행됩니다.
7종 의미 분류기는 기본값이 켜짐이며
**설정 → 기기 내 의미 분석 → 번들 7분류 모델 사용**에서 끌 수 있습니다. 끄면 이 모델을
호출하지 않습니다. 의미·광고 조건에 동작이 의존하는 알림은 fail-open으로 그대로 두고,
그 밖의 알림은 나머지 규칙 신호로 처리합니다. 신뢰할 수 있는 의미 결과는 규칙 조건을
충족할 수 있지만 낮은 신뢰도, `AMBIGUOUS`, 사용 불가, 시간 초과 결과도 알림을 그대로 둡니다.

통계에서 저장한 교정은 패키지별 로컬 피드백만 바꿉니다. 알림 말뭉치, 기울기, 모델
업데이트를 외부로 보내지 않습니다.

### 선택형 생성 LLM

**설정 → 기기 내 의미 분석**에는 고급 호환성 작업을 위한 별도의 MediaPipe `.task`
가져오기도 있습니다.

- 앱은 모델을 다운로드하지 않습니다.
- 신뢰할 수 있는 출처의 파일만 가져오세요.
- 파일은 앱 전용 저장소로 복사하고 이후 기록된 SHA-256과 비교합니다.
- 이 무결성 확인은 이후 변경을 찾지만 모델 게시자를 인증하지는 않습니다.
- 현재 빌드에는 자동 백그라운드 LLM 분석을 위한 검증 프로필이나 수동 추론 화면이
  없습니다.
- 검증되지 않은 모델은 네이티브 로딩 후 `Ready`가 될 수 있지만 알림 분석에는 사용하지
  않습니다.

AlarmControl은 이 모델을 제공하거나 학습하지 않습니다. 기술 사용자는
[사용자 LLM 안내](CUSTOM_LLM.ko.md)에 따라 호환되는 self-contained text-only `.task`를
준비할 수 있습니다. 학습 가중치, GGUF, safetensors, LoRA adapter, raw `.tflite`는 직접
가져올 수 없습니다.

규칙, 번들 의미 분류, 통계, 프로필, 자동화, 백업에는 선택형 LLM이 필요하지 않습니다.

## 문제 해결

### 아무 알림도 처리하거나 기록하지 않음

- **설정 → 앱 상태 → 알림 접근 권한: 준비됨**인지 확인합니다.
- **설정 → 필터링 사용**이 켜져 있는지 확인합니다.
- 규칙이 하나 이상 켜져 있는지 확인합니다.
- 관찰은 예상 결과만 기록합니다. 실제 취소·다시 알림에는 활성을 사용합니다.
- 권한을 허용한 뒤 새로운 대표 알림을 발생시킵니다.

### 규칙이 일치하지 않음

- 우선순위가 더 높은 규칙이 먼저 일치했는지 확인합니다.
- 앱 패키지와 채널 선택을 확인합니다.
- **이 규칙 시험하기**와 기록의 조건 트레이스를 사용합니다.
- 중요도, 대화, 포그라운드 서비스, 채널, 빈도, ML 신호가 없을 수 있습니다. 사용할 수
  없는 신호는 `UNKNOWN`이며 fail-open 처리됩니다.

### 일별 분석이 늦거나 비어 있음

Android 배터리 정책으로 주기 집계가 늦어질 수 있습니다. 실시간 기록은 일별 일정에
의존하지 않습니다. 빠른 요약이 중요하면 설정에서 배터리 상태를 확인하세요.

### 알림 상세가 없음

알림 도착 당시 상세 저장이 꺼져 있었거나, 앱이 제외됐거나, Android `SECRET` 알림이거나,
7일이 지났거나, 암호화 키가 삭제됐을 수 있습니다. 내용이 만료된 뒤에도 메타데이터는
남을 수 있습니다.

### 업데이트가 설치되지 않음

- 새 버전이 더 높은지 확인합니다.
- 신뢰하는 같은 Release에서 APK와 체크섬을 다시 받습니다.
- 서명 충돌은 보통 설치된 빌드와 새 APK의 키가 다르다는 뜻입니다.
- 확인한 백업을 만들기 전에는 앱을 제거하지 마세요.

### 외부 자동화가 거부됨

- **외부 자동화 허용**을 켭니다.
- 최신 토큰을 String extra로 사용합니다.
- AlarmControl 패키지 또는 수신기 component를 명시합니다.
- 설정의 최근 로컬 자동화 결과를 확인합니다.
- 로컬 요청 제한을 넘겼다면 잠시 기다립니다.

Samsung App Shortcut, 런처 바로가기, 빠른 설정은 이 토큰을 사용하지 않습니다.

### 가져온 LLM을 사용할 수 없음

파일이 없거나 바뀌었거나, 호환되지 않거나, 기기에서 너무 크거나, 현재 빌드가 지원하지 않을
수 있습니다. 신뢰하는 출처에서만 제거 후 다시 가져오세요. 핵심 규칙과 번들 분류는 LLM
없이 계속 작동합니다.

### 데이터를 삭제했거나 앱을 제거함

AlarmControl에는 클라우드 계정이나 OS 클라우드 백업이 없습니다. 사용자가 미리 만든 휴대용
백업이 있을 때만 복원할 수 있습니다.

## Android 플랫폼 한계

- Android가 알림을 게시한 뒤 필터링하므로 헤드업이 잠깐 보일 수 있습니다.
- 알림 플랫폼에 실제 영향을 주는 동작은 취소와 다시 알림뿐입니다.
- 다른 앱의 실제 알람이 알림으로 나타나지 않으면 제어할 수 없습니다.
- 다른 앱의 알림을 조용히 읽음 처리할 수 없습니다.
- 다른 앱의 알림 채널을 직접 바꿀 수 없으며 Android 설정만 열 수 있습니다.
- 통계에서 제외해도 이미 닫은 알림을 복구하지 못합니다.
- 신뢰도가 낮거나 누락된 로컬 신호는 알림을 그대로 둡니다.
- 자동 업데이트나 원격 모델 다운로드가 없습니다.
